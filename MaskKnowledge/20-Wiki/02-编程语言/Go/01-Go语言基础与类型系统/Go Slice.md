## 1. 从数组到 Slice：为什么需要切片

数组的长度是类型的一部分，例如 `[3]int` 和 `[4]int` 是两种不同的类型。数组适合表示固定长度的数据，但在实际开发中，我们经常需要一个长度可变、能够截取和追加元素的连续序列，因此 Go 提供了 Slice。

Slice 不是数组本身，而是对底层数组一段连续区域的描述。可以将它的运行时结构简化理解为：

```
type slice struct {
    array unsafe.Pointer // 指向底层数组
    len   int            // 当前可访问的元素数量
    cap   int            // 从切片起点开始可扩展的最大范围
}
```

因此，Slice 有三个必须同时理解的特征：

- Slice 变量保存的是底层数组指针、长度和容量，不直接保存全部元素；
- 多个 Slice 可以引用同一个底层数组；    
- 复制 Slice 只会复制 Slice 描述符，不会自动复制底层数据。


```
a := []int{1, 2, 3}
b := a
b[0] = 100

fmt.Println(a) // [100 2 3]
```

`a` 和 `b` 是两个 Slice 描述符，但它们仍指向同一个底层数组。

## 2. 截取 Slice：共享底层数组与 len、cap

### 二下标切片

```
s[low:high]
```

切片区间采用左闭右开规则：包含 `low`，不包含 `high`。

```
a := []int{1, 2, 3, 4}
b := a[1:3]
```

此时 `b` 包含 `a[1]`、`a[2]`：

```
a = [1 2 3 4]
b = [2 3]
```

长度的计算公式为：

```
len(b) = high - low = 3 - 1 = 2
```

容量不是当前切片中可见的元素数，而是从切片起点到底层数组容量边界的范围：

```
cap(b) = cap(a) - low = 4 - 1 = 3
```

所以：

```
len(b) // 2
cap(b) // 3
```

|属性|准确定义|本例结果|
|---|---|---|
|`len`|当前可通过下标直接访问的元素数量|2|
|`cap`|不重新分配数组时，从切片起点最多可扩展到的元素数量|3|

虽然 `cap(b) == 3`，但当前不能直接访问 `b[2]`，因为合法下标由 `len` 决定：

```
fmt.Println(b[2]) // panic: index out of range
```

容量表示可以扩展到哪里，不等于现在已经能访问到哪里。

### 为什么修改子切片会影响原切片

```
a := []int{1, 2, 3, 4}
b := a[1:3]
b[0] = 100
```

`b[0]` 与 `a[1]` 指向底层数组中的同一个位置，因此：

```
a = [1 100 3 4]
b = [100 3]
```

核心判断不是“两个 Slice 变量是否相同”，而是：

> 它们是否仍然引用同一个底层数组，以及操作的位置是否重叠。

## 3. append：是否影响原数据取决于剩余容量

`append` 会返回一个新的 Slice 描述符，因此应始终接收它的返回值：

```
s = append(s, value)
```

它是否创建新底层数组，主要取决于追加后的长度是否超过原容量。

### 容量足够：复用底层数组

```
a := []int{1, 2, 3, 4}
b := a[1:3] // len=2，cap=3
b = append(b, 100)
```

`b` 还有一个剩余容量，追加后的长度为 3，没有超过容量，因此复用原底层数组。`100` 写入的位置正好是原来的 `a[3]`：

```
a = [1 2 3 100]
b = [2 3 100]
```

这里不是在 `a` 的末尾新增元素，而是覆盖了共享底层数组中 `a[3]` 的值。`a` 的长度仍然是 4。

### 容量不足：分配新底层数组

当追加后的长度超过容量时，运行时通常会：

1. 申请容量更大的底层数组；
    
2. 复制原有元素；
    
3. 写入新增元素；
    
4. 返回指向新数组的 Slice。
    

扩容后，新 Slice 不再与原 Slice 共享同一个底层数组，因此后续修改通常不会相互影响。

新容量不是固定地“永远翻倍”。它受旧容量、目标容量、元素大小、内存对齐和当前 Go 版本的运行时实现影响。面试中更准确的说法是：

> 容量不足时，运行时会按扩容策略申请更大的底层数组并复制元素；具体容量增长结果属于实现细节，不应在业务代码中依赖固定倍数。

如果可以预估元素数量，应预分配容量以减少内存分配、元素复制和 GC 压力：

```
result := make([]int, 0, 1000)
```

## 4. 三下标切片：主动限制容量

三下标切片的语法是：

```
s[low:high:max]
```

其长度和容量分别为：

```
len = high - low
cap = max - low
```

例如：

```
a := []int{1, 2, 3, 4}
b := a[1:3:3]
```

得到：

```
b = [2 3]
len(b) = 3 - 1 = 2
cap(b) = 3 - 1 = 2
```

此时执行：

```
b = append(b, 100)
```

因为 `len(b) == cap(b)`，`b` 没有剩余容量，追加时必须分配新底层数组：

```
a = [1 2 3 4]
b = [2 3 100]
```

普通二下标切片与三下标切片的区别：

```
b := a[1:3]   // len=2，cap=3，append 可能覆盖 a[3]
b := a[1:3:3] // len=2，cap=2，append 会触发扩容
```

三下标切片只限制容量，不会立即复制数据。在触发扩容之前，它仍与原 Slice 共享底层数组：

```
a := []int{1, 2, 3, 4}
b := a[1:3:3]
b[0] = 100

fmt.Println(a) // [1 100 3 4]
```

## 5. 共享底层数组带来的典型覆盖问题

```
a := make([]int, 2, 4)
a[0], a[1] = 1, 2

b := append(a, 3)
c := append(a, 4)
```

`a` 的长度为 2、容量为 4。两次 `append` 都以长度为 2 的 `a` 为起点，因此写入位置都是底层数组的索引 2。

第一次追加后：

```
底层数组 = [1 2 3 _]
b = [1 2 3]
```

第二次追加会把同一位置覆盖为 `4`：

```
底层数组 = [1 2 4 _]
a = [1 2]
b = [1 2 4]
c = [1 2 4]
```

`a` 仍只显示两个元素，是因为 `append` 没有修改 `a` 自身描述符中的长度；但它们共享的底层数组已经发生变化。

这个案例体现了两个不同层面的变化：

- Slice 描述符：指针、长度和容量；
    
- 底层数组：真正保存的元素。
    

`append` 返回的新 Slice 可以有新的长度和容量，同时还可能修改原来共享的底层数组。

## 6. 需要独立数据时：copy 与 Clone

如果希望新 Slice 与原 Slice 完全独立，需要主动复制数据：

```
src := []int{1, 2, 3}
dst := make([]int, len(src))
copy(dst, src)
```

此后修改 `dst` 不会影响 `src`。

`copy(dst, src)` 实际复制的元素数为：

```
min(len(dst), len(src))
```

也可以使用标准库中的 `slices.Clone`：

```
import "slices"

dst := slices.Clone(src)
```

若要让多个追加结果彼此独立，可以写成：

```
b := append(slices.Clone(a), 3)
c := append(slices.Clone(a), 4)
```

## 7. nil Slice、空 Slice 与工程边界

### nil Slice 和空 Slice

```
var a []int
b := []int{}
c := make([]int, 0)
```

三者的长度和容量都是 0，但是否等于 `nil` 不同：

```
a == nil // true
b == nil // false
c == nil // false
```

三者都可以安全使用 `len`、`cap`、`append` 和 `range`。差异可能体现在接口语义或 JSON 序列化中：nil Slice 通常序列化为 `null`，非 nil 空 Slice 通常序列化为 `[]`。

### 小切片可能持有大数组

```
func getPart() []byte {
    data := make([]byte, 100<<20)
    return data[:10]
}
```

返回值虽然只有 10 字节，但它仍可能引用 100 MB 的底层数组，使整个数组无法被 GC 回收。可以复制真正需要的数据：

```
result := make([]byte, 10)
copy(result, data[:10])
return result
```

### 并发安全

Slice 本身不保证并发安全。多个 goroutine 同时修改相同元素、修改 Slice 描述符或执行 `append` 都可能产生 data race。工程中应使用锁、Channel、数据分片或让各 goroutine 操作独立副本。

### range 中的值副本

`range` 的 value 通常是元素的副本，修改它不会自动修改 Slice 中的原元素：

```
s := []int{1, 2, 3}
for _, v := range s {
    v *= 10
}

fmt.Println(s) // [1 2 3]
```

需要通过索引修改：

```
for i := range s {
    s[i] *= 10
}
```

## 8. 本轮容易混淆的关键点

### 误区一：`a[1:3]` 包含下标 3

错误理解：`b` 是 `[2 3 4]`。

正确理解：切片区间左闭右开，只包含下标 1 和 2，所以 `b` 是 `[2 3]`。

### 误区二：Slice 的 len 和 cap 总是相同

```
a := []int{1, 2, 3, 4}
b := a[1:3]
```

正确结果：

```
len(b) = 2
cap(b) = 3
```

`len` 看当前可访问范围，`cap` 看从切片起点到底层数组容量边界的可扩展范围。

### 误区三：append 只影响返回的新 Slice

容量足够时，`append` 会复用并修改共享底层数组，所以可能影响其他 Slice。容量不足并发生扩容后，新的 Slice 才会转向新的底层数组。

### 误区四：三下标切片会立即复制数组

三下标切片只限制新 Slice 的容量。它在扩容前仍共享原底层数组，直接修改元素仍会影响原 Slice。

## 9. 面试中的完整回答

> Go 的 Slice 是对底层数组一段连续区域的描述，运行时结构主要包含底层数组指针、长度和容量。`len` 表示当前可访问的元素数量，`cap` 表示从切片起点开始、不重新分配数组时能够扩展到的最大范围。多个 Slice 可以共享同一个底层数组，因此修改元素或在容量足够时执行 `append`，可能影响其他 Slice。执行 `append` 时，如果容量足够就复用原数组；容量不足时会申请更大的底层数组、复制原有元素并返回新的 Slice，所以必须接收 `append` 的返回值。三下标切片可以限制子切片容量，降低后续 `append` 意外覆盖原数组的风险，但它本身不会立即复制数据。需要完全独立的数据时，应使用 `copy` 或 `slices.Clone`。

一句话概括：

> 理解 Slice 的关键，是始终区分 Slice 描述符和底层数组，并判断不同 Slice 当前是否共享底层数据。
